# Token Monitor

## Register

product

## Users

macOS users working with several AI providers and accounts, including coding sessions in Codex and Claude Code. They glance at the menu between tasks, in both daylight and dim evening conditions; native system light/dark appearance remains the right default.

## Product Purpose

Show remaining subscription capacity and reset windows without interrupting work. Optional local project analytics answers where recorded token activity went, without pretending to measure quota share, cost, or productivity.

## Brand Personality

Quiet, factual, native. Preserve the existing compact utility rather than create a web-style analytics dashboard.

## Anti-references

No marketing screen, monetary estimates, crowded metric tiles, nested cards, decorative charts, duplicate thread-list main screen, or automatic cloud classification. Do not change authentication or provider refresh ownership for analytics.

## Design Principles

- Capacity stays the default. Optional analysis is a separate tab, hidden until enabled.
- Aggregate projects or topics first; reveal provider and thread details only on demand.
- Show observed data and incomplete coverage honestly; unavailable is not zero.
- Reuse native SwiftUI controls, existing typography, dividers, and system appearance.
- Keep local private usage metadata out of diagnostic exports and the public repository.

## Accessibility & Inclusion

Native controls with meaningful VoiceOver labels and keyboard operation. Fixed numeric alignment, readable caption text, wrapping/tooltips for long names, and no color-only distinctions. Verify both system appearances and bounded popover sizes; do not claim a formal accessibility audit.
